# Vibgrate CLI 2026.1111.1

_Released 2026-11-11_

This release of the Vibgrate CLI includes several important fixes and improvements to enhance the accuracy of scans across various project types. Notably, it addresses issues with dependency resolution in Ruby, Python, Terraform, and .NET projects.

## What changed

### Changed

- The SBOM dependency-scope table now documents Ruby `Gemfile` groups and Go `go.mod` rows.
- `vg build` now reads `Gemfile` dependencies into the code map as Ruby packages.

### Fixed

- `vg scan` resolves Gradle `libs…` aliases from `gradle/libs.versions.toml`, ensuring that lockfile versions are used for drift.
- Ruby Gemfile and gemspec scans now retain every version bound on a dependency, improving drift measurement.
- Terraform scans now keep every pinned version of a module, allowing for accurate drift reporting.
- Python projects that pin an interpreter now report that runtime and its lag correctly.
- `vg scan` and `vg sbom export` now include NuGet packages with versions pinned in Directory.Packages.props.
- Terraform scans no longer record non-registry module sources as dependencies, preventing unknown drift reports.
- `vg scan` reports a .NET runtime inherited from `Directory.Build.props`, improving runtime detection.
- `vg scan` reads OpenTofu `.tofu` files for provider and module drift accurately.
- Python requirements files now handle `-r` / `--requirement` includes correctly.
- A requirements line with a trailing comment is read without the comment, preserving URL fragments.
- `vg scan` reads the Ruby runtime from `ruby file: ".ruby-version"` correctly.
- Terraform registry modules with a `//subdir` suffix now get their latest version from the public registry.
- Yarn Berry lockfiles no longer list the project's own `@workspace:` entry as an SBOM component.
